# v0 research update — provider, event and projection boundaries

Status: **DRAFT DESIGN UPDATE; EXISTING IMPLEMENTATION CANDIDATES MUST BE RECONCILED**

## Why this update exists

The 2026-09-06 detailed design predates Kura/TeamAI research, the Agent Skills projection investigation and the advanced `program/ephemera-full-20260908-delivery` candidate. The authority/provenance design remains useful, but implementation work must now extend or qualify existing candidate components rather than assume an empty repository.

Read [`../../IMPLEMENTATION_CANDIDATE_MAP_2026-09-09.md`](../../IMPLEMENTATION_CANDIDATE_MAP_2026-09-09.md) before implementing this design.

## New decisions

### D11 — Evidence Event precedes new model-assisted Memory Candidate extraction

Harness events are normalized into a typed evidence/event envelope before an external/model Distillation Provider decides what should be remembered. User correction, verifier result, tool failure/retry, successful deterministic check and repeated operation become routable signals. Friction decides **what is worth examining**, not what is true.

This must feed/reconcile with the existing H03 memory trust boundary and H04 delta/event queue rather than creating a parallel evidence authority.

See [`../../EVIDENCE_EVENT_CONTRACT.md`](../../EVIDENCE_EVENT_CONTRACT.md).

### D12 — Memory/distillation are provider-capable, not necessarily external

HISTOS owns scope, source/evidence identity, anti-self-corroboration, Context compilation and provider admission. Existing H03 becomes the **native Memory Provider candidate**. A replaceable provider may store/recall memory or propose distillation candidates only if its output can be normalized without weakening H03-style trust/lineage/supersession requirements.

`distill-kura` is the first external experimental Memory+Distillation provider candidate because current source exposes deterministic quote verification, echo suppression and server-side read-only MCP enforcement. This is a comparison/integration path, not an adoption decision.

### D13 — Grounding receipts are first-class for model-assisted provider output

A provider-generated memory candidate should return enough deterministic grounding information to show which raw evidence survived its gate and which claims remain judgement/inference. Provider confidence text is insufficient. Native H03's host-attested claim/evidence model remains the acceptance floor; a Kura adapter may provide additional quote/surface grounding before H03-style admission.

### D14 — Recall utility is separate from epistemic support

TeamAI records recall/use feedback and uses friction to select sessions worth documenting. HISTOS may use those signals for routing/maintenance/policy experiments, but recall/popularity/repeated model mentions never increment independent support. Existing H03 lineage grouping remains authoritative for the native candidate.

### D15 — Procedural projection uses standards before bespoke sync

A reviewed procedural revision may be rendered as a portable Agent Skill package when the target harness supports the format. An A00 `VERIFIED` operation candidate may inform that procedure/tool projection, but A00 deliberately has no `ACTIVE` authority. Harness-specific files remain thin installation/UI/permission adapters.

See [`../../AGENT_SKILLS_RESEARCH_TARGET.md`](../../AGENT_SKILLS_RESEARCH_TARGET.md) and [`../../PROVIDER_PROJECTION_ARCHITECTURE.md`](../../PROVIDER_PROJECTION_ARCHITECTURE.md).

## Bootstrap strategy

Do not inject a full resident memory map or generated knowledge base into every session. Prefer a small stable pointer/Skill/rule that tells the harness when and how to ask HISTOS, followed by on-demand retrieval. Upstream Kura documents inconsistent client handling of MCP initialize instructions, TeamAI moved away from SessionStart auto-recall, and the existing H02 native service already proves an explicit four-tool read-only path on bounded Codex/OpenCode runs.

## Research gates

Before Kura becomes a qualified provider:

- compare recall against native/file lexical baselines under the same scopes/budgets;
- measure exact evidence descent, abstention and false recall;
- mechanically test read/write/store binding and guessed hidden-write calls;
- replay duplicate/echo/retrieved-memory contamination;
- measure model-assisted distillation cost/failure visibility;
- prove adaptation into H03/H04 trust/recovery semantics.

Before friction-triggered capture is adopted:

- replay sessions with independently identified reusable outcomes;
- measure trigger precision/recall and cost avoided;
- retain a positive route for smooth verified discoveries;
- feed trigger output to Evidence Event selection, not proof-count mutation.

Before Agent Skills projection is adopted:

- render one procedure from an accepted revision;
- validate against the open Agent Skills format;
- install the same core procedure into Codex and OpenCode through owned adapters;
- prove update/uninstall drift handling and permissions;
- measure discovery overhead and activation precision;
- preserve external activation authority.
